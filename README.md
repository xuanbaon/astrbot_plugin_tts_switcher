# TTS 声线切换（astrbot_plugin_tts_switcher）

在聊天里发一句 `/tts 示例`，当前会话的语音合成就换成那个声线；发 `/说=示例 今天风很好`，就让机器人用示例的声音念这句话；发 `/答=示例 今天天气怎么样`，让机器人用示例的声音**回复**这句，回完还是原来的声线。

AstrBot 本来支持给每个会话单独指定 TTS 提供商，但只能在面板的会话管理里一个一个点。日常在群里想换个声音、或者开了好几个声线想对比着听，开面板翻半天很麻烦。这个插件把「名字 → 提供商」的映射放到插件配置页，聊天里一句话就切，即时生效，不用重启核心。

## 特性

- **一句话切换**：`/tts 示例`、`/tts 通义`、`/tts 示例C`，名字自己定
- **一次性点播**：`/说=示例 今天风很好` 用指定声线念一句，之后仍用 `/tts` 选的声线，默认所有人可用
- **一次性回复**：`/答=示例 今天天气怎么样` 让机器人用示例的声音回复这句话，走正常的大模型回复，回完自动恢复，默认所有人可用
- **帮助随手查**：`/ttshelp` 一条指令看全所有用法，`/help` 末尾也会带上本插件的指令
- **声线可备注**：映射里每条都能写备注，`/tts 列表` 和 `/tts 状态` 里会显示，同名靠它区分
- **即时生效**：只写会话级偏好，不重启、不断线，切换后下一条回复就是新声音
- **别名与模糊匹配**：配了别名 `示例1,diyin`，发 `/tts diyin` 也行；名字先找完全对应的，没有就模糊搜，同一条声线的不同档（flash/plus）自动取靠前的那个，命中多个不同名字会问你写全，都没命中才回「没找到声线」
- **权限可控**：默认只有 AstrBot 管理员能用，也可以放开给所有人，或单独指定几个额外管理员
- **场景开关**：可以只允许私聊，或只允许群聊
- **会话级语音开关**：`/tts 关闭` 让这个群只发文字，`/tts 开启` 恢复，不影响别的群
- **一键回默认**：`/tts 默认` 清掉本会话设置，回到全局配置的默认 TTS
- **配置页下拉选**：声线映射里的提供商是下拉框，直接选面板里已有的语音合成提供商，不用手动抄 ID
- **自动读取供应商声线**：WebUI 的「声线控制台」会扫描「模型供应商」里所有文字转语音提供商，把它们的音色读出来；还没有对应声线的自动加载成一条，不用手抄 ID
- **绑定可改**：每条声线都绑定一个提供商 ID，供应商改名或删掉后页面会标出「供应商不存在」，可以下拉一键改绑
- **回复文案可改**：切换成功、没权限这些提示都能自定义，支持变量

## 安装

### 从插件市场 / 面板安装

面板 → 插件市场 → 搜索「TTS 声线切换」→ 安装 → 启用。

### 手动安装

把整个 `astrbot_plugin_tts_switcher` 目录放进：

```
AstrBot/data/plugins/astrbot_plugin_tts_switcher
```

重启核心，或在面板的插件管理里重载插件。

不依赖任何第三方库，`requirements.txt` 是空的。

## 配置

面板 → 插件 → TTS 声线切换。

### 声线控制台（WebUI 页面）

面板左侧「拓展功能 → 声线控制台」，插件详情页里也能进。这个页面读写的是同一份插件配置，保存即时生效。

**供应商声线（自动读取）**

页面顶部会把「模型供应商」里所有文字转语音提供商列出来，每个带上：

| 列 | 说明 |
| --- | --- |
| 供应商 | 提供商配置里写的名字 |
| 提供商 ID | 声线要绑定的那个 id，跟 `/tts 引擎` 列出的一致 |
| 模型 / 类型 | 例如 `qwen-audio-3.1-tts-flash`、`gsv_tts_selfhost` |
| 音色 / 权重 | 提供商自己的音色字段（如通义的 `qwen_audio_tts_voice`）或本地权重文件名 |
| 状态 | 已加入 / 未加入 |

- 点某一行「加入」或顶部「加载全部未加入」，会给这些音色各建一条声线（名字默认取供应商名，可改）
- 「启动时自动加载」开着时（配置项 `voices_auto_load`，默认开），插件启动就自动补上缺的声线
- 供应商在「模型供应商」里被改名、删除或重建后，旧声线会被标成 `供应商不存在`，页面上方出现改绑提示，选一个新提供商点「改绑」即可

**声线表**

118 条那种规模也扛得住：搜索、只看启用、行内改名字/提供商 ID/别名/备注、新增、删除、一键复制 `/说=名字 你好`、试听（当场合成一段播放）。

**分隔符说明**

- 声线名与正文之间：`/说=名字 正文` 的等号用 **半角 `=`** 或 **全角 `＝`** 都行；也认 **半角逗号 `,`**、**全角逗号 `，`**、冒号（`:` / `：`）、竖线 `|` 和空格
- 别名、白名单这类名单字段：**半角逗号 `,`**（英文输入法）与 **全角逗号 `，`**（中文输入法）都当分隔符，混用也可以；顿号、分号、竖线也认

### 声线映射（核心）

每一条对应一个能用的名字：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 名字 | 指令里要打的词 | `示例` |
| TTS 提供商 | 下拉选一个已启用的语音合成提供商 | `gsv_tts` |
| 供应商音色 | 可选。标明这条声线对应提供商的哪一档音色，只用于区分与去重；实际音色仍由提供商自身配置决定 | 留空 |
| 别名 | 可选，半角逗号 , 或全角逗号 ， 分隔 | `示例1,diyin,本地` |
| 备注 | 可选，只给人看 | `本地 GPT-SoVITS v2` |
| 启用 | 关掉就不在列表里 | 开 |

不知道提供商 ID 是什么？在群里发 `/tts 引擎`，插件会把当前所有语音合成提供商列出来，已经映射过的还会标上名字。

示例：配三条

```yaml
- name: 示例
  provider_id: gsv_tts
  alias: 示例1,diyin,本地
  note: 本地 GPT-SoVITS
- name: 通义
  provider_id: qwen-audio-3.1-tts-flash-si2
  alias: 云端,flash
- name: 男声
  provider_id: qwen-flash-xunanchuan
```

之后 `/tts 示例`、`/tts diyin`、`/tts 本地` 都会切到 `gsv_tts`。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/tts` | 看当前用的是哪个声线、是本会话指定还是全局默认 |
| `/tts 列表` | 列出所有可用声线，当前的会标出来；太长时切成多段用合并转发（聊天记录）发出，不会被截断 |
| `/tts <名字>` | 切换声线 |
| `/tts 默认` | 清掉本会话设置，回到全局默认 |
| `/tts 关闭` | 本会话不再合成语音 |
| `/tts 开启` | 恢复本会话语音 |
| `/tts 引擎` | 列出所有 TTS 提供商 ID |
| `/tts 帮助` | 显示帮助 |
| `/ttshelp` | 完整用法说明（`/tts`、`/说`、`/答` 全在里面） |
| `/说 <文本>` | 用当前声线念这句话（一次性），整段都当正文 |
| `/说=<声线> <文本>` | 用指定声线念这句话，不改当前设置，例如 `/说=示例 今天风很好` |
| `/说` | 显示 `/说` 的用法 |
| `/答=<声线> <文本>` | 让机器人用指定声线回复这句话，例如 `/答=示例 今天天气怎么样` |
| `/答 <文本>` | 用当前声线回复这句话 |
| `/答` | 显示 `/答` 的用法 |

指定声线一律用等号写法（半角 `=` 或全角 `＝`）。不带等号时 `/说`、`/答` 不做声线解析，整段都当正文——否则 `/说 罕见 骂谁罕见` 会被拆成声线「罕见」+ 正文「骂谁罕见」，跟「用当前声线念这句」的语义打架。等号后面的名字与正文之间仍认空格、逗号（半角 `,` / 全角 `，`）、冒号、顿号、竖线。

别名：`/TTS`、`/Tts`、`/声线` 效果一样。子命令也认英文，`list` / `status` / `reset` / `on` / `off` / `help` 都行。`/说` 的别名是 `/say`、`/speak`、`/念`、`/读`；`/答` 的别名是 `/回`、`/回复`、`/reply`、`/answer`；`/ttshelp` 也可以写 `/tts帮助`、`/声线帮助`、`/tts用法`。

三条指令的权限是分开的：`/tts` 会改掉会话声线，默认只给管理员；`/说` 只是念一句话、`/答` 只是让这一条回复换个声音，都不改设置，默认所有人都能用，靠冷却、字数/时长上限和白名单防刷屏。如果担心群里被玩坏，可以把「允许所有人使用」关掉，或者配一份声线白名单。

想不打命令也行：把「支持自然语言触发」打开，@机器人 说「用示例的声音说 今天风很好」效果一样（需被唤醒，未唤醒的消息不会响应，避免误触发）。

### 列表太长怎么办

声线多了以后 `/tts 列表` 会很长，一条消息装不下就会被平台截断。现在的做法是：正文超过「一条消息最多多少字」（默认 600）就按「每段多少条声线」（默认 40）切成几段，装进一条**合并转发**（聊天记录）里发出去，点开就能翻，内容一条不少。

- 平台不支持合并转发（不是 aiocqhttp/QQ），或者发送被拒（没权限、风控），会自动退回「分几条普通消息发」，也不会截断；
- 列表很短时还是老样子，一条普通消息；
- 嫌合并转发麻烦，把「长列表用合并转发发送」关掉，就会一直用分条发。

### 声线名怎么找（模糊匹配规则）

点名时不用写全名，规则是先严后松，最多三步：

1. **完全对应优先**——名字或别名跟你写的整段一模一样（后面紧跟分隔符或到结尾）就直接用，剩下的算正文。
2. **模糊兜底**——没有完全对应的，就把第一段拿去声线表里模糊搜（名字或别名里包含它）：
   - 只命中一个 → 就用它；
   - 命中的是同一个名字的不同档（`示例A flash` / `示例A plus` 这种只差档位后缀的）→ 视为同一个声线，取声线表里靠前的那个，不用写全名；
   - 命中好几个不同名字（比如只打 `示例`）→ 不猜，回你「能对上好几个，写的全一点」并列出候选，`/tts`、`/说=`、`/答=` 三处行为一致。
3. **一个都没命中**——回「没找到声线「XXX」。用 `/tts 列表` 看看有哪些。」，不会把名字当正文念出来。

为什么留这一层模糊：同一条声线在供应商/模型上常有 flash、plus 好几档，名字都很长，日常喊「示例A」就够了，非要写全 `示例A flash` 反而累。档位后缀（`flash` / `plus` / `gsv` / `v4` / `v2` / `pro`）本身不参与区分，只用来判断「这几个候选是不是同一条声线的不同档」；真要指定某一档，把后缀写全就行——完全对应优先，不会被模糊规则抢走。

例子：

| 你发的 | 实际用的 | 为什么 |
| --- | --- | --- |
| `/说=示例A flash 你好` | `示例A flash` | 名字完全对应 |
| `/说=示例A1 你好` | `示例A flash` | 别名完全对应 |
| `/说=示例A 你好` | `示例A flash` | 模糊命中两档（flash/plus），同基名取靠前的 |
| `/说=示例A plus 你好` | `示例A plus` | 写全档位，完全对应 |
| `/tts 示例` | 不切，列出候选 | 命中好几个不同名字，需要写全 |
| `/说=根本没这个 你好` | 提示没找到 | 一个都没命中 |

## 工作原理

AstrBot 的 TTS 提供商支持会话隔离，具体介质是共享偏好里的一条记录：

```
umo / provider_perf_text_to_speech = <provider_id>
```

插件切换声线时调的是 AstrBot 自己的 `provider_manager.set_provider(provider_id, ProviderType.TEXT_TO_SPEECH, umo)`，跟面板会话管理里点选走的是同一条路。因为它每次发消息都会重新读这条偏好，所以切换立刻生效，不需要重启。

`/tts 关闭` 改的是 `session_service_config.tts_enabled`，也是会话级。

插件不改全局配置，写的全部是当前会话这一条记录，出问题最多影响这个会话。

`/说` 走的是另一条路：先按映射拿到目标 provider 实例，直接调它的 `get_audio(text)` 拿到 wav，再用 `Record` 组件把语音发出去。全程不写任何偏好，所以「用某个声线念完就完」是天然成立的，中途合成失败也不会把会话设置改坏。合成结果走 `event.send()` 主动发送，不经过回复装饰阶段，因此不会被 TTS 再转一遍。

`/答` 更轻：指令阶段只做两件事——把「这一轮要用哪个 provider」记在内存里，然后把事件里的消息文本改成去掉 `/答=示例 ` 之后的正文，**不产出任何结果**，好让后面的 LLM 阶段照常接收这句话。等大模型把回复写好，`on_decorating_result` 钩子再按记下的 provider 把文字合成语音、替换掉消息链（长回复按句末标点切段，一条语音一段）。因为全程不碰会话偏好，所以不需要事后还原，也不会出现「别人插一句话被念成临时声线」这种事；合成失败就原样发文字。

`/help` 的集成是靠运行时包装内置的 `HelpCommand.help` 实现的（AstrBot 的 `/help` 只列 reserved 内置指令，第三方插件的指令不会出现在里面）。只改内存里的方法，不动核心文件，插件卸载后自动失效；核心结构变了会安静跳过，不影响插件本体。

## 常见问题

**切了没声音？**
先看 `/tts` 里「本会话语音」是不是关着。再看那个 TTS 提供商本身在别的会话能不能出声，本地服务没启动的话谁都救不了。

**提示「没有找到 id 为 xxx 的 TTS 提供商」？**
提供商被删了、改名了，或者刚加了还没重启核心。发 `/tts 引擎` 对照一下真实 ID。

**改名后插件没反应？**
插件的 provider 列表是启动时读的。新增或删除 TTS 提供商之后要重启一次核心，插件才能看到。

**`/说` 提示「没合成出来」？**
提示里会带引擎名和真实报错。本地 GPT-SoVITS 要先确认那个端口（比如 9880 / 9881）在跑；云端提供商看 API Key 是否还有效。首句合成超过「合成超时」也会报这个，把超时调大试试。

**`/答` 只回了文字、没有语音？**
说明合成没成功或者没赶上。看日志里 `[tts_switcher] /答 合成失败` 那一行带着真实报错；本地服务刚启动时首句要加载模型，把「合成超时」调大一点。另外回复如果带图片、@ 之类的内容，插件会原样发文字，不会硬转语音。

**`/ttshelp` 在 `/help` 里没出现？**
先看配置里「在 /help 里附上本插件指令」是不是开着；再确认插件是启用状态。如果 AstrBot 升级后内部结构变了，注入会安静跳过，`/ttshelp` 本身不受影响。

**为什么不用命令前缀也能触发？**
取决于 AstrBot 的唤醒设置。默认需要 `/` 前缀，或者 @机器人。这个插件走标准指令注册，行为和别的插件一致。

## 开发

```bash
git clone https://github.com/example/astrbot_plugin_tts_switcher
```

单文件实现，逻辑都在 `main.py`：

- `_voices()` 读配置里的映射（含备注）
- `_match()` 名字匹配（精确 → 包含 → 反向包含）
- `_switch()` 真正调 `provider_manager.set_provider`
- `_parse_voice_text()` 只在等号写法下工作：把 `/说=示例 你好`、`/答=示例 你好` 等号后面的内容拆成声线和正文（不带等号时整段都是正文）
- `_synthesize()` 带超时和重试地调 `provider.get_audio()`
- `decorate_answer()` 在装饰阶段把 `/答` 的那一条回复换成语音
- `_install_help_patch()` 把指令摘要挂到内置 `/help` 末尾
- `tts_cmd()` / `say_cmd()` / `answer_cmd()` / `ttshelp_cmd()` 四个指令入口

提 PR 前请保持 `python -m py_compile main.py` 通过。
